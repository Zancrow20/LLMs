# ТЗ: аудитор безопасности (Security Reviewer)

Аудитор безопасности — локальная мультиагентная система для AppSec- и SecOps-анализа. Она ищет уязвимости в исходном коде (Python, JS/TS, C#, Go, Java, SQL, Dockerfile), проверяет утечки секретов, аудирует зависимости на CVE и разбирает журналы событий (`.csv`, логи). Все модели работают локально на MacBook, исходный код и логи не уходят в облако.

## 1. Цель и пользователь

Пользователь — разработчик, AppSec-инженер или аналитик ИБ. Он работает на своём ноутбуке и не может отправлять проприетарный код, секреты и логи во внешние облачные сервисы. Система получает проверяемый файл и вопрос и возвращает верифицированный технический отчёт. Каждое число, номер строки, идентификатор CWE/CVE и уровень критичности в отчёте опирается на вывод сканера или кода.

## 2. Сценарии

---|---|---|---

UC-2 | «Найди захардкоженные секреты и ключи в `vuln_app.py`» | Поиск API-ключей, токенов и паролей, расчёт энтропии Шеннона, маскирование секретов | `scanner`, `scan_secrets`, `validator`
UC-3 | «Проанализируй лог `auth_access.csv` на брутфорс и аномалии трафика» | Код на Python в песочнице, подсчёт статусов 401/403 по IP и объёма выгрузки | `analyst`, `run_python`, `validator`

## 3. Функциональные требования

- **FR-1.** Система принимает файлы из `workspace/` через CLI: исходный код (`.py`, `.js`, `.ts`, `.cs`, `.go`, `.java`, `.sql`, `Dockerfile`, `.yaml`), файлы зависимостей (`requirements*.txt`, `package.json`, `*.csproj`), таблицы и логи (`.csv`). Размер файла — до 50 МБ.
- **FR-2.** Система проверяет существование, расширение и размер файла до запуска агентов. Если файл не подходит — система называет причину и не запускает граф.
- **FR-3.** Decision-модель определяет тип задачи (`scanner`, `analyst`, `chat`) и сложность (`hard`, 0–1).
- **FR-4.** Роутер выбирает LLM по сложности: `gemma4:e4b` по умолчанию (`hard < 0.85`), `gpt-oss:20b` для сложных многошаговых задач (`hard >= 0.85`).
- **FR-5.** Агент `scanner` вызывает инструменты AppSec-анализа через MCP: `scan_code`, `scan_secrets`, `check_dependencies`, `read_code_slice`.
- **FR-6.** Агент `analyst` выполняет Python-код для разбора логов и таблиц только в песочнице. Timeout — 30 с.
- **FR-7.** Если код удаляет файлы, обращается к сети или читает вне `workspace/` — гибридный гейт (regex + decision-модель) блокирует выполнение и запрашивает подтверждение пользователя (`interrupt`).
- **FR-8.** Валидатор на LLM другого семейства (`qwen3:8b`) проверяет каждое число, номер строки, CWE/CVE и факт ответа по выводам тулов (`evidence`). После 2 отказов ответ уходит с пометкой «(Ответ не проверен валидатором.)».
- **FR-9.** Короткая память хранит историю сессии по `thread_id` в SQLite и переживает перезапуск.
- **FR-10.** Долгая память хранит факты с датой начала и конца действия (`valid_at` / `invalid_at`). Новый факт закрывает противоречащий старый.
- **FR-11.** Агенты загружают процедурные скиллы (`code-audit`, `secret-triage`, `log-forensics`, `answer-with-evidence`) по запросу тулом `load_skill`.
- **FR-12.** Если данных не хватает — система отвечает «не знаю» и называет, чего не хватает.
- **FR-13.** Каждый запрос пишет трейс в Langfuse. Метрики и структурированные JSON-логи уходят в Grafana (Prometheus + Loki).
- **FR-14.** Пользователь оценивает ответ командами `/good` и `/bad`. Оценка попадает в трейс Langfuse.

## 4. Нефункциональные требования

- **NFR-1. Офлайн.** По умолчанию система не обращается в интернет. Исходный код и логи не покидают хост.
- **NFR-2. Память.** Все компоненты работают на MacBook с 24 ГБ unified memory (лимит Metal GPU — 17.8 ГБ).
- **NFR-3. Время ответа.** p95 — до 30 с для аудита файла кода или лога. p95 — до 10 с для вопроса без файла.
- **NFR-4. Изоляция.** Агент и исполняемый код работают в microVM `sbx`. Из песочницы открыты только порты 11434 (Ollama), 8765 (MCP), 3000 (Langfuse), 4318 (OTLP). Интернет закрыт.
- **NFR-5. Доступ к файлам.** MCP-сервер принимает пути только внутри `workspace/` (защита `safe(path)` от Path Traversal).
- **NFR-6. Стек.** Компоненты — open-source или open-weights. Исключения названы и обоснованы в отчёте.
- **NFR-7. Текст.** В коде, промптах, логах и ответах нет эмодзи.
- **NFR-8. Трейсы и логи.** Срок хранения — 14 дней. Строковые поля в логах обрезаны до 500 символов, секреты маскируются.
- **NFR-9. Язык.** Система отвечает на языке последнего сообщения пользователя. Язык в `USER.md` — настройка по умолчанию: явное указание пользователя в диалоге приоритетнее.

## 5. Вне рамок

- Динамическое тестирование (DAST) и активное сетевое сканирование внешних хостов.
- Обучение и дообучение моделей.
- Веб-интерфейс (система работает через CLI).
- Многопользовательский режим.

## 6. Критерии приёмки

Метрика | Порог
---|---
Доля решённых задач golden-набора | ≥ 70%
Выбор нужного тула и аргументов | ≥ 90%
Обоснованность ответа (LLM-as-a-Judge) | ≥ 0.9
Точность роутера на 30 размеченных запросах | ≥ 85%
Precision и recall валидатора на 40 кейсах | ≥ 0.8
Факт из прошлой сессии найден | ≥ 90%
Устаревшие факты в ответах | 0%
Успешные prompt injection через комментарии в коде | 0
p95 времени ответа для аудита файла | ≤ 30 с
Сценарии демо (аудит кода, память, гейт) после перезапуска | 3 из 3
