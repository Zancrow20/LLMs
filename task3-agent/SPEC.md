# ТЗ: медиа-ассистент

Медиа-ассистент — мультиагентная система. Она отвечает на вопросы о файлах пользователя: видео, аудио, картинках, таблицах CSV. Все модели работают локально на MacBook, файлы не уходят в облако.

## 1. Цель и пользователь

Пользователь — аналитик или исследователь. Он работает на своём ноутбуке и не хочет отправлять файлы во внешние сервисы. Система получает файл и вопрос и возвращает короткий отчёт. Каждое число в отчёте опирается на вывод модели или кода.

## 2. Сценарии

ID | Запрос | Что делает система | Агенты и тулы
---|---|---|---
UC-1 | «Сколько людей прошло в кадре?» + видео | Детекция с трекингом, таблица «класс → число уникальных объектов» | `media`, `detect_video`, `validator`
UC-2 | «Расшифруй аудио и оцени тональность» + аудио | Расшифровка, затем тональность: `sentiment` для английского текста, LLM для русского | `media`, `transcribe`, `sentiment`
UC-3 | «Посчитай статистику по CSV и построй график» + CSV | Код на pandas в песочнице, график в `workspace/out/` | `analyst`, `run_python`, `validator`
UC-4 | «Что на картинке?» + картинка | Топ-5 классов ImageNet с уверенностью | `media`, `classify_image`
UC-5 | «Сравни с прошлым анализом этого файла» | Поиск прошлых фактов о файле, сравнение | `orchestrator`, `memory_search`
UC-6 | «Запомни: отчёты пиши на русском и кратко» | Запись предпочтения в долгую память | `memory_writer`, Graphiti
UC-7 | «Что ты умеешь?» | Ответ малой LLM без тулов и без валидатора | `orchestrator`

## 3. Функциональные требования

- **FR-1.** Система принимает файл через CLI: видео (`.mp4`, `.avi`), аудио (`.wav`, `.mp3`), картинку (`.jpg`, `.png`), таблицу (`.csv`). Размер файла — до 200 МБ.
- **FR-2.** Система проверяет тип и размер файла до запуска агентов. Если файл не подходит — система называет причину и не запускает граф.
- **FR-3.** Decision-модель определяет тип задачи (`media`, `analyst`, `chat`) и сложность (`hard`, 0–1).
- **FR-4.** Роутер выбирает LLM по сложности: `gemma4:e4b` по умолчанию, `gpt-oss:20b` или облачную LLM для сложных задач. Облачная LLM работает, только если её включил пользователь.
- **FR-5.** Агент `media` вызывает ML-модели задания 1 через MCP: `transcribe`, `sentiment`, `classify_image`, `detect_video`.
- **FR-6.** Агент `analyst` выполняет код только в песочнице. Timeout — 30 с.
- **FR-7.** Если код удаляет файлы, обращается к сети или читает вне `workspace/` — система спрашивает подтверждение пользователя.
- **FR-8.** Валидатор на LLM другого семейства проверяет каждое число и факт ответа по выводам тулов. После 2 отказов ответ уходит с пометкой «не проверено».
- **FR-9.** Короткая память хранит историю сессии по `thread_id` и переживает перезапуск.
- **FR-10.** Долгая память хранит факты с датой начала и конца действия. Новый факт закрывает противоречащий старый.
- **FR-11.** Агенты загружают скиллы по запросу тулом `load_skill`.
- **FR-12.** Если данных не хватает — система отвечает «не знаю» и называет, чего не хватает.
- **FR-13.** Каждый запрос пишет трейс в Langfuse. Метрики и логи уходят в Grafana.
- **FR-14.** Пользователь оценивает ответ командами `/good` и `/bad`. Оценка попадает в трейс.

## 4. Нефункциональные требования

- **NFR-1. Офлайн.** По умолчанию система не обращается в интернет. Облачная LLM включается отдельным флагом.
- **NFR-2. Память.** Все компоненты работают на MacBook с 24 ГБ unified memory.
- **NFR-3. Время ответа.** p95 — до 60 с для видео до 30 с. p95 — до 10 с для вопроса без файла.
- **NFR-4. Изоляция.** Агент и код работают в microVM `sbx`. Из песочницы открыты только порты 11434 (Ollama), 8765 (MCP), 3000 (Langfuse), 4318 (OTLP). Интернет закрыт.
- **NFR-5. Доступ к файлам.** MCP-сервер принимает пути только внутри `workspace/`.
- **NFR-6. Стек.** Компоненты — open-source или open-weights. Исключения названы и обоснованы в отчёте.
- **NFR-7. Текст.** В коде, промптах, логах и ответах нет эмодзи.
- **NFR-8. Трейсы.** Срок хранения — 14 дней. Содержимое файлов в трейсах обрезано до 500 символов.
- **NFR-9. Язык.** Система отвечает на языке запроса или на языке из `USER.md`.

## 5. Вне рамок

- Обучение и дообучение моделей.
- Веб-интерфейс. Система работает только через CLI.
- Несколько пользователей одновременно.
- Поиск в интернете.
- Потоковое видео и видео длиннее 5 минут.

## 6. Критерии приёмки

Метрика | Порог
---|---
Доля решённых задач golden-набора | ≥ 70%
Выбор нужного тула и аргументов | ≥ 90%
Обоснованность ответа (LLM-as-a-Judge) | ≥ 0.9
Точность роутера на 30 размеченных запросах | ≥ 85%
Precision и recall валидатора | ≥ 0.8
Факт из прошлой сессии найден | ≥ 90%
Устаревшие факты в ответах | 0%
Успешные prompt injection через файлы | 0
p95 времени ответа для видео до 30 с | ≤ 60 с
Сценарии демо (видео, память, гейт) после перезапуска | 3 из 3

Пороги — черновые. Их уточняют результаты бенчмарка LLM и первые прогоны evals.
